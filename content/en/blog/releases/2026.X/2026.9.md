## Release Notes

### Overview

2026.9 is the latest [Release][] of the next generation of {{% ctx %}} and improves on the [2026.3][] release in the following areas:

* Capability
* Security
* Performance
* Usability
* Third-Party Support
* Installation
* Upgrade
* Documentation

### Features

#### Capability

##### Added AI-generated flow documentation

{{% ctx %}} can now generate a human-readable document for each flow in a package, using an AI model server that runs on your own network. Each document describes what the flow does, its variables, the flows it calls and each workspace in execution order, and ends with a review of the flow.

Documentation is requested and retrieved through a new API, and generation can be limited to set times so that it runs out of hours.

For how to install it, see [Add Flow Documentation to {{% ctx %}}][].

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]
* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]
* [{{% ctx %}} Innovation AI Application][]
  * [{{% ctx %}} Documentation Service][]
* {{% ctx %}} App Server Install Scripts
* {{% ctx %}} Upgrade Scripts

##### Added running execution counts and details

The [{{% ctx %}} Gateway][Gateway] now shows how many executions are running. The Operations Overview shows the total, the Packages page shows a count for each package version, and a new Running Executions tab lists the executions running on a package version. The counts and lists are also available through the [{{% ctx %}} API Gateway Service][].

Affected Components:

* [{{% ctx %}} Gateway][Gateway]
* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]

The following Microsoft 365 blocks have been added:

* Get Emails Using Microsoft 365
* Delete Email Using Microsoft 365
* Delete Emails Using Microsoft 365
* Download Attachment Using Microsoft 365
* Download Attachments Using Microsoft 365
* Move Email Using Microsoft 365
* Move Emails Using Microsoft 365
* Update Email Using Microsoft 365
* Update Emails Using Microsoft 365

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]
* [{{% ctx %}} Gateway][Gateway]

##### Added proxy support to Send Email Using Microsoft 365

The Send Email Using Microsoft 365 block has a new optional `Proxy` property, so email can be sent through an HTTP or HTTPS proxy.

The Execute SSH Command block can now authenticate with a private key in a PuTTY PPK file, including a password-protected PPK file.

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]

##### Updated Create Process from BPMN XML

Create Process from BPMN XML in the [{{% ctx %}} Gateway][Gateway] now uses `gpt-5` as the default model. The model-call timeout is configurable, and the built-in retry behaviour of the OpenAI API client is disabled.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]

##### Added SNMP enumeration translation

When a MIB is loaded, enumeration values defined for an object are stored with that object. When a trap varbind matches a MIB object that has enumeration values for the varbind value, the value is translated to the enumeration name. If the object has no enumeration for that value, the value is left unchanged.

Affected Components:

Configuration settings management has been extended to more {{% ctx %}} services. When a service starts, any new or missing settings are added to the configuration store and applied.

#### Security

##### Added certificate-based OAuth and mTLS

Machine-to-machine applications can now be registered to authenticate with either a client secret, using the OAuth 2.0 client-credentials grant, or with certificates, using mutual TLS (mTLS). Each application uses the one method chosen when it is registered.

Affected Components:

* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]

##### Added TCP passthrough for API Gateway mTLS

The load-balancer configuration for the [{{% ctx %}} API Gateway Service][] now passes TLS traffic straight through, so applications using mTLS can authenticate through the load balancer without any manual changes to its configuration.

Affected Components:

* {{% ctx %}} App Server Install Scripts
* {{% ctx %}} Upgrade Scripts
* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]

##### Required HTTPS for a remote AI model server

When the AI model server is on a different machine from the documentation service, the connection must now use HTTPS and an encrypted API key. A model server on the same machine can still use HTTP.

Affected Components:

* [{{% ctx %}} Innovation AI Application][]
  * [{{% ctx %}} Documentation Service][]

##### Keeping portal sign-in tokens out of the browser

Portal sign-in now uses an encrypted session cookie, so sign-in tokens are not held in the browser. A failed sign-in does not create a session, and the password is not written to the audit record.

Affected Components:

* {{% ctx %}} Portal

##### Added an optional OpenID scope and UserInfo

Sign-in can now request the `openid` scope to also receive an ID token, and a new UserInfo endpoint returns details of the signed-in user. Sign-in without the `openid` scope works as before.

Affected Components:

* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]

##### Updated the SSL best practices scripts

The SSL best practices scripts now disable Triple DES 168 and the SHA hash, and set a stronger list of cipher suites, including TLS 1.3 cipher suites on Windows Server 2022 and later. Communication with Microsoft services, including NuGet, continues to work after hardening.

Affected Components:

* {{% ctx %}} App Server Install Scripts

#### Performance

##### Debug resume returns without timing out

Resuming a flow from edit debug now passes the dependencies required to resume, rather than only the downstream dependencies of the parent flow. On a large package, resume returns to debug mode in under five seconds, including on a single-node cluster and on a multi-node cluster.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]
* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} Execution Management Service][]

#### Usability

##### Updated {{% ctx %}} Portal navigation

Sign-in and sign-out are available from the portal shell. The portal can be given a timeout, in seconds, for calls to the [{{% ctx %}} API Gateway Service][]. A call that exceeds the timeout, or a gateway that cannot be reached, is reported separately from a rejected sign-in.

Affected Components:

* {{% ctx %}} Portal

##### Limited log redaction to sensitive property names

Log redaction now applies only to sensitive properties, such as `Password`, and to encrypted values. Other values, including text that happens to contain the word password, are now written to the logs in full.

### Bug Fixes

#### Capability

##### Oracle connections no longer fail with ORA-01882

A bug was fixed where an Execute Data Command connection to Oracle failed with `ORA-01882` when the database did not include the `Etc/UTC` time zone region. {{% ctx %}} now falls back to the hour offset `+00:00` when the managed Oracle driver time zone region is not supported by the database.

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]

##### For Each loop accepts a null collection

A bug was fixed where a flow failed to start when a null input variable was passed to a block property whose type is an interface. This includes the For Each loop when its collection is a variable with a null value.

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Collection expressions translate for object and generic inputs

A bug was fixed where a collection expression such as `[1,2,3]` failed to translate on an input property of type `T`, `object` or `dynamic`. The same fix applies to Run Flow block inputs.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]
* [{{% ctx %}} Block Packages][Blocks]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Create Process from BPMN XML accepts large XML

A bug was fixed where creating a process from BPMN XML failed when the Base64 XML was too large to pass as a command-line argument. The process is now created, the generated XML is valid BPMN 2.0 with the required namespaces, and an ampersand in a name is encoded.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]

##### Child flow running executions no longer show an empty identifier

A bug was fixed where a child flow started by a Run Async Flow block was returned by the running-executions API with an empty identifier (`00000000-0000-0000-0000-000000000000`). The child flow's identity is now returned. A parent flow also continues when a child flow pauses on a breakpoint on its start block.

Affected Components:

* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Execution started and ended messages are retried

A bug was fixed where the [{{% ctx %}} Execution Service][] stopped sending execution started and execution ended messages after a send failed. Failed details are put back on the queue and the service keeps trying to send them.

Affected Components:

* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Renamed licence file is picked up

A bug was fixed where copying a licence into the licence folder under a temporary name, then renaming it to `Cortex.lic`, did not start licence validation. The [{{% ctx %}} Execution Service][] now leaves the licence-missing error and can run flows after the file is renamed.

Affected Components:

* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} Licence Management Service][]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

#### Usability

##### Reduced spacing around blocks created from BPMN XML

A bug was fixed where blocks created from BPMN XML were placed with a large amount of empty space inside the workspace. The margin around the blocks is now 54px.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]

##### Schedules that cannot fire are rejected

A bug was fixed where a schedule that could never fire, because all of its CRON execution times were in the past, could be saved and could break the [{{% ctx %}} Scheduling Service][] on a role change. These schedules are now rejected in the [{{% ctx %}} Gateway][Gateway] and through the API.

Affected Components:

* [{{% ctx %}} Gateway][Gateway]
* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} API Gateway Service][]
  * [{{% ctx %}} Scheduling Service][]

#### Performance

##### Reduced memory growth when calling child flows

A bug was fixed where a flow that repeatedly called child flows with output data grew in memory for as long as it ran. Memory use now stays bounded. Get running executions, and other flows on the same node, continue to start and finish while that flow runs.

Affected Components:

* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Reduced memory growth from workspaces and exception handling

A bug was fixed where a flow that repeatedly entered and exited a workspace or state block, or repeatedly threw and handled exceptions, grew in memory for as long as it ran.

Affected Components:

* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

#### Scalability

##### Flows continue when a node enters maintenance

A bug was fixed where putting a node into maintenance with `Cortex.Node.Maintenance.ps1` caused running flows to log `FlowNotFoundException` with `AlreadyClosedException` from Run Flow blocks, and the same class of failure from collection blocks, while the node was changing state.

Affected Components:

* [{{% ctx %}} Block Packages][Blocks]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

##### Semaphores are acquired during a naming-service reconfiguration

A bug was fixed where a block waiting on a semaphore failed when the Service Fabric Naming service was mid-reconfiguration and cluster queries threw `FabricTransientException`. The semaphore is now acquired and the flow continues.

Affected Components:

* [{{% ctx %}} Innovation Core Application][]
  * [{{% ctx %}} Concurrency Management Service][]
* [{{% ctx %}} Innovation Execution Application][]
  * [{{% ctx %}} Execution Service][]

#### Installation

##### Clean installation no longer reports startup errors

A bug was fixed where services reported an error on first start-up after a clean installation.

Affected Components:

* {{% ctx %}} App Server Install Scripts
* [{{% ctx %}} Innovation Core Application][]
* [{{% ctx %}} Innovation Execution Application][]

#### Upgrade

##### Shared configuration is updated on upgrade

A bug was fixed where an upgrade left the `shared` application setting at `false`. After the upgrade, `shared` is `true`.

Affected Components:

* {{% ctx %}} Upgrade Scripts
