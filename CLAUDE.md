# CORTEX Product Portal

See @README.md for project overview and @package.json for available npm commands.

## Build & Dev

- Build: `npm run build` (runs Hugo then generates the Lunr offline-search index)
- Dev server: `hugo server` (live reload at http://localhost:1313)
- Lint markdown: `node mdlint.js` or `npx markdownlint-cli2 "content/**/*.md"`
- Validate TOML cross-references: `node scan-and-clean-toml.js`
- Sync latest version alias: `powershell ./createLatest.ps1`

## Content Structure

All documentation lives under `content/en/docs/{VERSION}/`. Active versions:

| Version   | Status        |
|-----------|---------------|
| `2026.3`  | Current latest (also copied to `content/en/docs/latest/`) |
| `2025.9`  | Supported     |
| `2025.3`  | Supported     |
| `2024.9`  | Supported     |

Sections within each version: `FAQs/`, `Getting Started/`, `Guides/`, `Whats New/`, `Reference/`, `Overview/`, `Tutorials/`

Static assets (images, downloads) go in `content/static/`.

## Page Frontmatter

Every markdown page requires:

```yaml
---
title: "Full Page Title"
linkTitle: "Short Nav Label"
description: "One-line description of what this page covers."
weight: 10
---
```

Section index files are named `_index.md`. Use `weight` to control navigation order within a section.

## Hugo Shortcodes

| Shortcode | Use |
|-----------|-----|
| `{{% ctx %}}` | Renders the product name — use instead of hardcoding "CORTEX" in prose |
| `{{% alert title="Note" %}} ... {{% /alert %}}` | Callout / warning box |
| `{{< url path="Key.Path.To.Url" >}}` | External URL resolved from `data/urls.toml` |

When adding a new external URL reference, add the entry to `data/urls.toml` first, then reference it with the `{{< url >}}` shortcode.

## Markdown Rules

`MD033` (inline HTML) and `MD013` (line length) are disabled globally. See `content/.markdownlint.json`.
Always specify the language on fenced code blocks (e.g., ` ```powershell `, ` ```json `).

## Git Workflow

- Branch naming: `Feature/short-description` (e.g., `Feature/add-configure-code-analyser-faqs`)
- PRs target `main`; GitHub Actions deploys to GitHub Pages automatically on merge
- NEVER commit files in `docs/` — it is generated Hugo output, not source
- NEVER commit files in `themes/` — it is a git submodule
- NEVER edit `content/en/docs/latest/` directly — it is regenerated by `createLatest.ps1`

## Key Scripts

| Script | Purpose |
|--------|---------|
| `createLatest.ps1` | Copies current latest version to `content/en/docs/latest/` |
| `scan-and-clean-toml.js` | Validates all `{{< url >}}` path references against `data/urls.toml` |
| `mdlint.js` | Runs markdownlint with VS Code-compatible defaults |
